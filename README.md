# 캐릭터 해석 (겉과 속 · 충돌 가치) — Tavern Helper 스크립트

작업노트의 모듈 1·2를 구현한 MVP입니다. 확장(Extension)이 아니라 **Tavern Helper(JS-Slash-Runner) 스크립트**로 만들었고, MVU가 있으면 MVU 변수로 "지금 이 순간"의 상태를 추적합니다.

| 모듈 | 무엇을 하나 | 어디에 저장 |
|---|---|---|
| ① 겉과 속 | 보여주는 모습 / 진짜 욕구 / 두려움·상처 / 스스로 믿는 착각 | 캐릭터 변수 `캐릭터해석` (카드와 함께 이동) |
| ② 충돌하는 가치 쌍 (최대 3개) | A vs B, 기우는 쪽(0~100), 부딪힐 때 행동, 반대로 골랐을 때 대가 | 위와 같음 |
| MVU 동적 층 | `캐해.가면균열`(속마음이 얼마나 새어 나오나), `캐해.기울기[]`(쌍별 현재 기울기), `캐해.최근갈등` | 메시지 변수 `stat_data.캐해` (스와이프마다 분기) |

## 설치

> ⚠️ Tavern Helper 스크립트는 임의의 JavaScript를 실행합니다. 이 스크립트는 캐릭터 카드 내용을 **지금 연결된 AI API로만** 보내고(분석할 때), 결과를 캐릭터 변수에 저장합니다. 외부 서버로 보내는 것은 없지만, 실행 시 jsDelivr CDN에서 pinia·dedent·klona 라이브러리를 불러옵니다.

1. 실리태번에 **Tavern Helper(酒馆助手)** 가 설치·활성화돼 있어야 합니다.
2. Tavern Helper 패널 → 스크립트 라이브러리 → **가져오기** → `캐릭터해석.json`
   - 모든 캐릭터에 쓰려면 **전역 스크립트**, 특정 카드에만 쓰려면 **캐릭터 스크립트**로 가져오세요.
3. 스크립트가 켜져 있는지 확인 → 입력창 위에 **캐해 분석 / 캐해 편집** 버튼이 생기고, 확장 패널에 **캐릭터 해석** 서랍이 생깁니다.

### MVU 연동 (선택)

- **이미 MVU zod 카드인 경우**: 아무것도 추가하지 마세요. 카드의 MVU를 자동으로 감지합니다 (패널에 "MVU: 감지됨").
- **MVU가 없는 카드에서 동적 층을 쓰고 싶은 경우**: `비MVU카드용/` 의 두 파일을 **캐릭터 스크립트**로 가져오고, 패널에서 **"변수 출력 형식도 주입"** 을 켜세요.
  1. `1-mvu.json` — MVU 본체
  2. `2-MVU-빈-변수구조.json` — JSON Patch 갱신을 받기 위한 빈 구조
- MVU가 없으면 **고정 모드**로 동작합니다: 분석 결과만 주입하고 변수 추적은 하지 않습니다.

## 사용 순서

1. 1:1 채팅에서 캐릭터를 연다 → **캐해 분석** 클릭
2. 분석이 끝나면 편집 창이 열림 → 내용 확인·수정 (라벨 대신 **행동 문장**으로)
3. **저장** → 다음 답변부터 주입됩니다
4. 편집 창 아래 **"AI에게 들어가는 프롬프트 미리보기"** 로 실제 주입 내용을 확인할 수 있어요

## 설정 (확장 패널 > 캐릭터 해석)

| 설정 | 기본값 | 설명 |
|---|---|---|
| 답변 생성 때 주입하기 | 켬 | 끄면 저장된 해석이 있어도 주입하지 않음 |
| 주입 깊이 | 2 | 0이면 맨 끝(가장 강함). 숫자가 클수록 앞쪽 |
| 주입 역할 | system | |
| 분석 결과 언어 | 한국어 | 지시문은 항상 영어, 내용만 이 언어로 |
| 가면 균열·가치 기울기를 MVU 변수로 추적 | 켬 | MVU 감지 시에만 작동 |
| 변수 갱신 규칙 주입 | 켬 | AI에게 `캐해.*` 를 언제 바꾸는지 알려줌 (depth 0) |
| 변수 출력 형식도 주입 | 끔 | **MVU 카드가 아닐 때만** 켜기. MVU 카드는 이미 형식 항목이 있음 |
| 한 턴 최대 변화량 | 10 | AI가 크게 바꿔도 스크립트가 이 범위로 잘라냄 |

## 동작 방식 요약

- **분석**: `generateRaw` 로 프리셋 없이 카드(설명·성격·시나리오·첫 메시지·예시 대화)만 보내 JSON을 받습니다. 결과는 zod로 검사하고, 글자 수 초과·이상값은 잘라서 고칩니다.
- **주입**: `injectPrompts` 로 채팅 안(깊이 설정값)에 `<character_insight>` 블록을 넣습니다. 매 생성 직전(`GENERATION_AFTER_COMMANDS`)에 최신 MVU 값으로 다시 만듭니다.
- **MVU 보정**: `VARIABLE_INITIALIZED` 에서 새 채팅의 시작값을 넣고, `VARIABLE_UPDATE_ENDED` 에서 빠진 값 채우기·0~100 범위·턴당 변화량 제한을 적용합니다.
- 카드 자체 MVU 구조(`registerMvuSchema`)는 느슨한 객체로 등록되므로 `캐해` 키가 지워지지 않습니다.

## 테스트 체크리스트

- [ ] 버튼 2개와 확장 패널 서랍이 보인다
- [ ] **캐해 분석** → 편집 창이 열리고 4칸 + 가치 쌍 2~3개가 채워진다
- [ ] 저장 후 F12 콘솔에 `[캐릭터해석] loaded` / 오류 없음
- [ ] 미리보기에 `<character_insight>` 가 보인다
- [ ] (MVU) 답변 후 Tavern Helper **변수 관리자** → 메시지 변수 → `stat_data.캐해` 가 생긴다
- [ ] (MVU) 가면균열이 한 턴에 10 넘게 변하지 않는다
- [ ] 캐릭터를 바꾸면 그 캐릭터의 해석으로 바뀐다 (없으면 주입 안 함)

문제가 생기면 F12 콘솔의 빨간 오류, Tavern Helper **로그 뷰어**, 재현 순서(1~5줄)를 보내 주세요.

## 아직 안 되는 것

- 그룹 채팅 (캐릭터가 하나로 정해지지 않아 비활성화)
- 장면별 선별 주입(모듈 4), 관계·상황별 변화표(모듈 3), 단면화 경고(모듈 6)
- 분석 전용 API/모델 따로 지정 (현재 연결된 API를 그대로 사용)

## 소스 수정·재빌드

`src/` 폴더를 [tavern_helper_template](https://github.com/StageDog/tavern_helper_template) 의 `src/캐릭터해석/` 으로 복사 → `pnpm install` → `pnpm build` → `dist/캐릭터해석/index.js` 내용을 스크립트에 붙여 넣으세요.

| 파일 | 역할 |
|---|---|
| `schema.ts` | zod 데이터 구조, 글자 수 제한, 설정 기본값 |
| `analyze.ts` | 분석 프롬프트(영어)와 JSON 파싱 |
| `prompt.ts` | 주입 프롬프트·MVU 갱신 규칙(영어) |
| `runtime.ts` | 주입, MVU 이벤트 보정, 버튼 동작 |
| `store.ts` | 설정(스크립트 변수)·해석(캐릭터 변수) 저장 |
| `Panel.vue` / `Editor.vue` | 설정 서랍 / 편집 창 |
